ShipCodes Mapping — Help Guide

Translate each partner's shipping method into the codes the ERP expects

info What ShipCodes Mapping Is

When an ASN (shipment) is sent to a marketplace, each order line's incoming carrier text has to be turned into the two codes the ERP expects:

swap_horizOverview

An order arrives with a shipping method such as FEDEX GROUND. Per customer, that value is mapped to a Level Of Service (e.g. G2) and a Shipping Method code (e.g. FedExGround). These used to be hardcoded per customer inside the ASN stored procedure — this screen holds those same values as editable rows, so a change is a row edit, not a code change.

view_column What Each Column Means

storefront
Customer The trading-partner account the mapping belongs to, e.g. AMA1005 or TAR6266P.
local_shipping
Source Method The incoming carrier value to match, exactly as it arrives on the order — e.g. FEDEX GROUND.
rule
Match Type EXACT for a full value, or LIKE for a starts-with match (see below).
badge
Level Of Service First output — the service-level code sent in the ASN, e.g. G2, fedex, UPSG.
qr_code
Shipping Method Second output — the carrier method code, e.g. FedExGround. Blank for Walmart (it uses another source).
flag
Default Marks the customer's fallback row, used when nothing else matches. Its Source Method is empty.

rule Exact vs Like

check_circleEXACT

The incoming value must match the Source Method exactly — e.g. FEDEX GROUND matches only FEDEX GROUND.

manage_searchLIKE

A starts-with match. Type just the base text — for example UPS — and the % is added for you, so it matches UPS Ground Service, UPS SurePost… and so on. You never type the % yourself.

flag The Default Row (Mandatory)

priority_highEvery customer needs one Default

When you set up mapping for a new customer, you must add exactly one row marked as Default. Tick the Default box — the Source Method is cleared automatically and left empty. It is the fallback used whenever the shipping method does not match any EXACT or LIKE row. A customer may have only one Default; a second is rejected.

add_circle Adding a Mapping

Click Add and fill in the fields (all are required for a new row):

1
Customer Pick the trading-partner account this mapping is for.
2
Match Type EXACT for a full value, or LIKE for a starts-with base such as UPS.
3
Source Method The incoming carrier value. Leave it empty only when the row is the Default.
4
Level Of Service & Shipping Method The two output codes the ASN will carry for this method.
5
Default Tick only for the customer's single fallback row — this empties the Source Method.

warning_amber When Saving Is Blocked

flagDefault already exists

"Customer [ … ] already has a Default row. Only one Default is allowed per customer." — edit the existing Default instead of adding another.

content_copyDuplicate mapping

"A mapping for customer [ … ] and source method [ … ] already exists." — the same customer, source method and match type is already mapped; edit that row.

build Editing and Deleting

edit
Edit Change any value. The Default and duplicate rules are re-checked on save.
delete
Delete A confirmation shows the row first. After deleting, that method falls back to the next matching rule (or the Default).

lightbulb Good to Know

scheduleWhen changes take effect

The mapping is read every time an ASN runs — no restart needed. The next run picks up your change.

shopping_basketWalmart is special

For Walmart only the Level Of Service is mapped; its Shipping Method output comes from the address, so that column stays blank on Walmart rows.

groupsEach partner is independent

Every customer has its own rows. There is no shared "all customers" mapping — a partner with no rows produces no codes for its ASN.
