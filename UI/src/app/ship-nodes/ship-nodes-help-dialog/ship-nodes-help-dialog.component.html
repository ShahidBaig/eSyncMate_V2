Ship Nodes — Help Guide

Map each warehouse to the ship node a marketplace expects

info What Ship Nodes Are

A ship node is the marketplace's own name for one of your warehouses:

hubOverview

Your ERP knows warehouses by codes like L10 or L55. Marketplaces know the same locations by their own identifiers — a GUID for Target Plus and Amazon, a long number for Walmart. Every inventory feed uses this screen's mapping to translate one into the other. If a warehouse is not mapped here, its stock is never sent to that marketplace.

storefront Two Sets of Mappings, One Screen

add_circle Adding a Mapping

Click Add and fill in four fields:

1
Partner Choose Partner Ship Nodes or Walmart Ship Nodes — this decides where the mapping is stored.
2
Customer Pick the trading partner account this warehouse ships for.
3
Warehouse Start typing to pick an existing code, or enter a brand-new one for a warehouse being added.
4
Ship Node Paste the identifier exactly as the marketplace portal shows it — a wrong character means the feed silently skips that warehouse.

rule The One-to-One Rule

A customer's warehouse can hold only one ship node, and that ship node cannot be reused on another warehouse of the same customer. If a mapping already exists you will see a warning instead of a duplicate:

warning_amberWarehouse already mapped

"Warehouse [ L10 ] already has a ship node for customer [ AMA1005 ]." — edit the existing row instead of adding a second one.

warning_amberShip node already used

"Ship node [ … ] is already mapped to another warehouse of customer [ … ]." — check the marketplace portal; two warehouses cannot share one node.

build Editing and Deleting

edit
Edit Change the customer, warehouse or ship node. The same one-to-one rule is re-checked on save.
delete
Delete A confirmation shows the customer, warehouse and node first. Once removed, inventory for that warehouse stops going to the marketplace.

lightbulb Good to Know

inventory_2DEFAULT warehouse

A row with warehouse DEFAULT is the fallback node used when stock is not tied to a specific warehouse. Leave it in place unless you know it is no longer needed.

scheduleWhen changes take effect

Mappings are read each time an inventory feed runs — no restart needed. The next scheduled run picks up your change.

visibilityWhat you can see

You only see mappings for the customers assigned to your account. Admins see every partner.
